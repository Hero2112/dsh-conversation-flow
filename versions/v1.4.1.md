# v1.4.1 — 修复「面板能开、左侧对话列表空白」

> 发布日期：2026-11-06 · 插件包版本：`@local/dsh-conversation-flow@1.4.1` · 仓库：https://github.com/Hero2112/dsh-conversation-flow

## 问题现象

DSH 升级到 0.2.0 系列（GUI 端口从 13825 变成 1566、并加了访问鉴权）后，打开「对话流」面板：
- **面板本身正常打开**（侧边栏图标在、画布在）；
- **左侧对话列表一片空白**，画布上的节点也没有对话信息；
- 插件像是"半死"状态：界面在、数据全空。

## 根本原因

插件的 Host 半在 `apply()` 里一次性获取两个服务：

```js
const server = ctx.get('webServer');   // 注册 /conversation-flow/api/*
const tools = ctx.get('tools');        // 注册 conversation_flow Agent 工具
```

而 `export const inject = []`（空依赖）——**Loader 在启动时并发装载各插件行**，本插件可能先于 `webServer` / `tools` 挂载就被 apply。那时两个 `ctx.get()` 都拿到 `undefined`，于是：

- HTTP 路由一条都没注册 → 面板请求 `/conversation-flow/api/state` 得到 **404** → 左侧列表空、画布无数据；
- Agent 工具没注册 → 工具列表里也没有 `conversation_flow`；
- 客户端半是独立的浏览器 bundle，照常加载，所以**面板能打开**——于是表现为"插件在、但没数据"。

在 `plugin_manager` 里停用再启用插件就能恢复（此时服务都已就绪），也可以证明是启动顺序问题。

## 修复

1. **声明真实依赖**：`export const inject = ['tools', 'webServer']`。Cordis 会等这两个服务就位后再调用 `apply`，彻底避开启动竞态。
2. **双保险**：即使某个 profile 里服务迟到，`apply` 也不再"查一次就放弃"——路由与工具改为 `ctx.inject(['webServer'])` / `ctx.inject(['tools'])` 的延迟注册，服务出现时自动补注册。
3. 重构：路由处理器抽成 `routeHandler` + `registerRoutes(server)`，工具定义抽成 `buildToolDefinition()` + `registerTool(tools)`，两条注册路径共用同一份实现。

## 验证

- Host mock 测试 **36/36**：新增「inject 必须声明 tools + webServer」的回归保护；连跑 4 次全绿。
- 页面服务端渲染 **7/7** 不受影响（客户端未改动）。
- 修好后真机 `GET http://127.0.0.1:1566/conversation-flow/api/state` 返回 200：`tool: registered`、`sessions: 47`、`topics: 4`；`conversation_flow` 工具重新出现在工具表里。
- 定时节点/自动协调逻辑未改（仅注册时机变化）。

## 影响与升级

- 只改 Host 半（`index.js`），`client.js` 未变；升级后**刷新页面**即可，不需要重新设置画布。
- 已有画布、主题、节点属性数据文件 `$DSH_HOME/conversation-flow/graph.json` 不受影响（本次升级前后未改动其结构）。
