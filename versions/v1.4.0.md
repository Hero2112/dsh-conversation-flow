# v1.4.0 — 多主题画布（一个主题 = 一条工作流）

> 发布日期：2026-11-04 · 插件包版本：`@local/dsh-conversation-flow@1.4.0` · 仓库：https://github.com/Hero2112/dsh-conversation-flow

## 这一版实现了什么

**「主题」= 一张独立的工作流画布。** 你可以建多个主题（如「素材审核流水线」「直播间数据日报」「客服质检」），每个主题里放不同的对话节点、连不同的数据通道、设不同的定时；切主题就切整套工作流，互不干扰。

| 能力 | 说明 |
|---|---|
| 多主题 | 画布顶部新增主题条：下拉切换、`＋新建主题`、`改名`、`删除`（删除需二次确认，且至少要保留一个主题） |
| 画布隔离 | 节点、通道、节点头上的作用/输出/定时、画布外观（背景色/网格）都按主题各自保存 |
| 后台照常跑 | 定时任务、自动协调、pending 兑现**遍历所有主题**，不是只跑当前显示的那个主题 |
| 数据迁移 | 旧版（v1 单画布）的 `graph.json` 自动迁移成一个名为「默认主题」的主题，原有节点/通道/外观不丢 |
| 状态文件 | `graph.json` 升级为 v2：`{ version: 2, activeTopicId, topics: [...], transfers: [...] }` |

## 怎么用

1. 打开「对话流」，顶部主题条默认是「默认主题」；
2. 点 `＋ 新建主题` → 输入名字（如「素材审核」）→ 自动切到新画布；
3. 在左侧对话列表点对话放进画布、拖圆点连线、点节点设置作用/输出/定时——这些都属于当前主题；
4. 下拉切回别的主题，画布立即切换成那套工作流；
5. 不需要的主题点「删除」（再点一次确认）。

## 接口

- `GET /conversation-flow/api/state`：新增 `topics`（每个主题的 id/名称/节点数/通道数/定时数/更新时间）、`activeTopicId`；`graph` 仍是**当前主题**的节点/通道/外观（并多了 `topicId`、`topicName`）
- `POST /conversation-flow/api/topic`：`{ action: 'create' | 'select' | 'rename' | 'delete', topicId?, name? }`
- `POST /api/graph`、`/api/node`、`/api/run`：可用 `topicId` 指定主题，不传就用当前主题
- `POST /api/coordinate`：按 edgeId 自动定位所属主题
- 工具 `conversation_flow`：新增 `topics`（列出主题）与 `topic`（`topic_op`: create/select/rename/delete）；`state` 先输出当前主题，`node`/`run` 可跨主题按节点 id 或 session id 定位

## 验证到什么程度

- Host mock 测试 **35/35**，新增 4 项覆盖：默认主题存在、新建/切换/改名/删除且画布互相隔离、**非当前主题里的定时节点照常触发**、工具 topics/topic 操作
- 页面服务端渲染测试 **7/7**，新增主题条（下拉 + 新建 + 改名 + 删除）渲染检查
- 真机升级：旧 `graph.json`（v1 单画布，含 2 节点 1 通道）自动迁移为「默认主题」，节点与连线保持；`GET /api/state` 返回 `topics`/`activeTopicId`
- 构建产物 `dev/client.js` 245 KiB，Host/Client 语法检查通过

## 已知限制

1. 定时任务、自动协调是**跨主题**生效的——不存在的"仅当前主题运行"模式；要停某个主题的定时，逐个节点关掉即可。
2. 主题之间不共享节点/通道：同一个对话可以同时出现在多个主题里，但每个主题各自一份节点设置。
3. 删除主题会连同其中节点与通道一起删除，不可撤销（会二次确认）。
4. 其余限制同 1.3.0：目标对话必须打开、被驱动的轮次消耗额度、传输仅文本。
