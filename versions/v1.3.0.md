# v1.3.0 — 节点属性真正驱动运行

> 发布日期：2026-11-04 · 插件包版本：`@local/dsh-conversation-flow@1.3.0` · 仓库：https://github.com/Hero2112/dsh-conversation-flow

## 这一版实现了什么

把「节点设置」里的三个字段从**描述性文字**变成**真正影响运行**的开关：

| 字段 | 实际行为 |
|---|---|
| 节点作用 `role` | 执行节点时，这段文字作为任务指令投进该节点自己的对话并唤醒它（`agent.followup`）——对话会真的按职责开始干活；留空则节点退化为纯数据推送（不唤醒、不消耗额度） |
| 输出内容 `output` | 非空时该节点总是推送这段**固定文本**，且立即推送、不等对话产出；留空则在被驱动的这一轮结束后取对话产出（按连线类型：摘要 / 最近 N 轮 / 完整记录） |
| 是否定时 `schedule` | 开启后 Host 每 20 秒扫描一次，到 `everyMinutes` 就执行节点：先驱动对话，再把结果推给全部下游通道 |

执行流水线：`定时到点 / 立即执行 / 工具 run` → 有作用则驱动对话 → 有固定输出则立即推送，否则进入「执行中」等待该轮 `turn/end`（`completed`）→ 兑现推送并清除状态。

配套：`pendingAt` 记录执行中（10 分钟超时失效）、与全局自动协调共用 15 秒防回环（同一次轮次只推一次）、失败有明确错误（节点对话未打开 / 目标对话未打开 / 无下游通道）。

## 怎么用

1. 侧边栏点「对话流」进入画布，从左侧对话列表点一个对话放到画布上；
2. 点击节点 → 右侧「节点设置」：填**节点作用**（如「按投放数据给出优化清单」）、**输出内容**（需要固定下发时填）、打开**定时**并设间隔；
3. 点「立即执行」验证：该对话会收到一条 `【对话流·节点执行】你在画布中的职责：…` 消息并开始工作；这一轮结束后结果沿通道推给下游；
4. 下游对话需要处于打开状态（有活动 Agent）才能收到投递。

## 接口

- `GET /conversation-flow/api/state` — 画布、通道、节点属性、传输记录、`diagnostics` 自检
- `POST /conversation-flow/api/graph` — 保存画布（含 `canvas` 外观）
- `POST /conversation-flow/api/node` — 改 role / output / schedule
- `POST /conversation-flow/api/run` — 立即执行，返回 `kicked / pending / sent / failed / error`
- `POST /conversation-flow/api/transfer` · `POST /conversation-flow/api/coordinate`
- Agent 工具 `conversation_flow`：`list / state / node / run / transfer / link / coordinate`

## 验证到什么程度

- Host 半 mock 测试 **31/31**（含：作用驱动对话、轮次结束兑现恰好一次、固定输出直推、定时单窗口只驱动一次、关闭定时后不再驱动、pending 清除、工具 run 路径）
- 页面服务端渲染测试 **6/6**（页面结构、内联样式、空态、画布工具栏与网格、无未解析占位符）
- 真机：插件安装 `enabled: true`、`diagnostics.tool = "registered"`、state 接口 190ms 返回 41 个对话；节点属性改动即时落盘
- 传输真实投递：以标准 `user` 消息经 `agent.followup` 进入目标对话 inbox（已验证消息正文与来源标记）

## 已知限制

1. 目标对话必须处于打开状态（有活动 Agent），否则返回 `target-not-live` 并提示先打开；
2. 被节点驱动的那一轮会消耗模型额度（等于在该对话手动发一条消息），定时频率要按需设置；
3. 传输内容是文本，图片/附件不随传输搬移；
4. `/conversation-flow/api/*` 不在 DSH 全局鉴权内，插件自身拒绝跨站请求且只监听 loopback；
5. 定时任务只有一层：不做依赖编排（A 完成后才跑 B），需要链式时用通道的「自动协调」。
