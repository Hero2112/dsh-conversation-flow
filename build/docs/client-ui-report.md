## 3. Component contract

**Components, not lazy factories.** `E\dsh-cordis-client-runner\lib\client.js:2221-2222`:

```ts
export type SlotComponent<P> = (props: P) => ReactNode;
```

`ctx.slots.register(options, Component)` where `Component` is a React function component. Reusable
*lazy factories* are a separate registry (`registerFactory` / `SlotFactoryMap`), not needed for a page.

**`main` entry props.** `renderSlot("main", {}, { entryKey })` passes **empty owner props**, and the
renderer composes the final props as
`{...kit, ...entryInject, ...slotInject, ...ownerProps}` — owner props win
(`E\dsh-client-ui-renderer\lib\client.js:773-810`, `standardKit` at `736-767`). For a root-scope entry:

- `kit` = root standard props + `renderFactorySlot` (+ `t` if `locale` declared, + `renderSlot`/
  `renderSlotChain`/`SessionProvider` if `children` declared, + `useStore`/`actions` if `store` given)
  + this entry's `inject(...)` result;
- final props for `main` therefore are: the **root standard hooks**, `t` (when `locale` is set),
  `renderFactorySlot`, whatever your `inject()` returns, then `{}` from the owner.

Root standard props (catalog `'main'` entry, lines 4385-4395; sources:
`E\dsh-client-ui-session\lib\client.js:1104-1113`, `E\dsh-client-ui-layout\lib\client.js:621`,
`E\dsh-client-ui-workspace\lib\client.js:5040-5043`, `E\dsh-api-remote-access\lib\client.js:664`,
`E\dsh-client-resources\lib\client.js:176`):

```

useResource            — keyed hook: useResource(address)
useWorkspaces(selector)
usePanelInfo(selector) — selector over { activePanelId: string | null }
useSessions(selector)
useSessionStatus(selector)
```

Hook naming rule (verified): `standardHookPropName(name)` = `` `use${name[0].toUpperCase()}${name.slice(1)}` ``
— `F\` offset 484830: `function kI(e){return`use${e[0]?.toUpperCase()??""}${e.slice(1)}`}`.

**Critical consequence for a "conversation graph canvas":** a `main` keyed entry is **root-scoped**,
so it receives **no** session/conversation binding (`useConversation`, `useSession`, `sessionId`,
`useProjection`, `useAccess` appear only on `session`/`session-maybe` slots such as
`main.conversation`). A full-page graph must therefore obtain transcript/turn data from the Host
(see §6) or through the `sessions` client service — not from slot props.

**`sidebar.panellist` entry props**: exactly `{ size: number, active: boolean }` plus the same root
standard props (catalog `ownerProps` at line 5773; call site at
`E\dsh-client-ui-sidebar\lib\client.js:226-229`). Shipped icons only use `size`
(`PluginsPanelIcon({ size })`, `E\dsh-client-ui-plugin-manager\lib\client.js:4289-4291`;
`TaskManagerIcon({ size })`, `E\dsh-client-ui-schedule\lib\client.js:6874-6876`).

**Locale-label resolution**: `resolveSlotLabel(label)` = `typeof label === "function" ? label() : label`
(`F\` offset 484828: `function $I(e){return typeof e=="function"?e():e}`). Sidebar projection:
`E\dsh-client-ui-sidebar\lib\client.js:567-584` re-reads every `label` thunk in `syncPanels()` and
subscribes to `ctx.locale.subscribe(syncPanels)`.

**Error isolation requirement**: every entry render is wrapped in `SlotErrorBoundary`
(`E\dsh-client-ui-renderer\lib\client.js:631-646`):

```js
componentDidCatch(error) {
  console.error(`slot entry crashed in '${this.props.slotKey}':`, error);
  this.props.onEntryError(error);
}
render() { if (this.state.failed) return h(Anchor, { "data-slot-error": this.props.slotKey }); … }
```

A throwing page component blanks the page with a `<div data-slot-error="main">`, logs
`slot entry crashed in 'main'`, and (for non-chain kinds) abdicates the entry
(`reportEntryError(..., { abdicate: spec.kind !== "chain" })`, line 1140). There is no
Suspense/lazy integration in slot rendering ("Slot rendering has no Suspense integration or
per-entry lazy loading" — `E\dsh-client-ui-renderer\README.md:95`), so the page must render a real
node synchronously (spinner/empty state), not suspend.

**Does a known slot exist for "the whole page body"?** No dedicated body slot: `main` *is* the
whole center-column body (the conversation renders its own shell into it as `main.conversation`).
`centerCol` is `display:flex; flex-direction:column; min-width:0; overflow:hidden`
(`E\dsh-client-ui-layout\lib\client.js:73`), so the page root must be `height:100%` (see §4).

## 6. Host RPC from a third-party client bundle

### 6a. `ctx.remote.*` is build-generated — **not usable** by a hand-authored bundle

- `ctx.remote` is populated by mounting **generated** contributions:
  `E\dsh-api-remotes\lib\client.js:23750-23797` mounts a literal array of `TYPERT_REMOTE`/`TYPERT_REMOTE$n`
  objects, each compiled into the bundle:
  ```js
  for (const contribution of [TYPERT_REMOTE$25, …, TYPERT_REMOTE]) disposers.push(await ctx.remote.$mount(contribution));
  ```
- `$mount` validates the contribution and registers descriptors whose inputs are checked against
  strict codecs: `E\dsh-api-gateway\lib\client.browser.js:1669-1744`
  (`validateContribution` → `requireStrictInputs(descriptor)`, `callerCtx.typert.remotes.register(contribution)`).
- Those artifacts are produced at build time by the Typert generator and exposed as `./typert` /
  `./remote` package exports (`E\dsh-typert-loader\README.md:12, 47-49, 91-93`; e.g.
  `E\dsh-api-session-controller\package.json` exports `"./typert"` and `"./remote"`). Hand-authoring
  a valid contribution plus the matching Host dispatch descriptors is not a supported/verified path —
  **do not plan on it**. Report this as *verified that it is generated; unverified that a hand-made
  contribution is rejected* (I did not attempt a mount).

### 6b. Practical path: a Host route + plain same-origin `fetch()`

Two route kinds exist on the Host, with very different auth:

**(i) `ctx.connection.fetch.register(...)` — under `/api`, authenticated.** Preferred.

```js
ctx.effect(() => ctx.connection.fetch.register({
  path: "/api/conversation-graph/nodes",
  methods: ["GET"],
  requestBody: "buffered",           // or "streaming"
  fetch: (request) => Promise.resolve(Response.json({ nodes, edges })),
}), "conversation-graph: route");
```

- Shape and call site verified: `E\dsh-client-ui-deliverables\lib\index.js:48-60`
  (`path: "/api/present.host"`, `requestBody: "buffered"`, `fetch: () => Promise.resolve(Response.json(…))`);
  also `E\dsh-client-file-upload\lib\index.js:170-176` (`requestBody: "streaming"`),
  `E\dsh-api-session-controller\lib\index.js:2482-2490`.
- Path must live under `/api`: `assertFetchRoute()` at `E\dsh-client-connection\lib\index.js:973-977`
  (`endpointFromPath("/api", route.path) === undefined` → throw).
- Auth: these routes are dispatched inside the `/api` prefix handler, which performs
  trust + authentication before reaching the route:
  `E\dsh-client-connection\lib\index.js:1044-1058` (`connection.admit(req)` → 401/403, else
  `bridge(req, res, fetchHandler, admission.peer, …)`), and a fetch route only answers an owner peer
  (`:826-832`: `if (peer.principal.kind !== "owner") return new Response("forbidden", {status:403})`).
- **Consequence for the page**: a same-origin `fetch('/api/conversation-graph/nodes')` needs **no
  header and no token**. The signed browser-session cookie is host-only, `Path=/`, and sent
  automatically; the Host/Origin fence passes because the request is same-origin. (`authorizeIndex`
  mints the cookie at page load — `E\dsh-client-connection\lib\index.js:805-810`.)

**(ii) `ctx.webServer.register({kind:'exact'|'prefix', path, handler})` — no auth at all.** Works, but
carries no identity.

- API and matching: `E\dsh-host-webserver\lib\index.js:320-333` (`register(route)`, duplicate
  `(kind,path)` throws), `:376-394` (request listener: match → `route.handler(req, res)`, then
  `fallback`), `:495+` (`match`: exact over the whole table, then longest prefix). Handler signature is
  raw node `(req: IncomingMessage, res: ServerResponse)`, not a `Request`/`Response`.
- **Auth finding (decisive):** the webserver applies **no** authentication and **no** origin policy.
  Its own README says so — `E\dsh-host-webserver\README.md:12` ("It knows no harness concepts…") and
  the limitations section ("**No server-wide authentication or origin policy** — route owners such as
  `dsh-client-connection` enforce their own request policy"). Verified in code: the connection's
  `admit()` (trust fence `isTrusted` + cookie/API auth) is called **only** inside the `/api` prefix
  handler and the `/connect` handler — `E\dsh-client-connection\lib\index.js:1035-1066`. A plugin route
  registered directly on `webServer` never passes through `admit()`, so it is reachable by anyone who
  can reach the port (loopback by default; anything the bind host allows). If you use this path, the
  page's `fetch` still needs no header — but *nothing* authenticates the caller, so do not serve
  user/session data from it without your own check.

Note also: `/plugins/*` (client bundle serving) is registered on `webServer` by `dsh-client-modules`
and is likewise outside `/api` — evidence that "custom non-/api path" is a normal, unauthenticated
route class in this app.

`/api` binding for third-party bundles: the Host half must `inject: ['connection']` (the service key is
`connection`; `HostConnectionService` sets `super(ctx, "connection")`,
`E\dsh-client-connection\lib\index.js:709-710`), and the page calls `fetch('/api/…')`. This is the
recommended RPC path; keep the payload JSON and `cache-control: no-store`.
